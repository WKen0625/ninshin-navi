# 記事の書き方（content/articles）

記事は「手続きの答え」ではなく、読みもの。答え（次にやること・締切・金額）は `data/` と画面が返す（設計原則2）。記事はその周りの「考え方」「準備」「背景」を書く。

## 置き場所と形

- `content/articles/<slug>/ja.md` と `en.md`。slug は英小文字・数字・ハイフン。日本語版と英語版は同じ slug に置く（片方だけでもよい）。
- 先頭に `---` で囲んだ見出し情報（YAML）。`title`・`description`・`published` は必須。コロンを含む文字列は `"` で囲む。
- `pr`: 製品の紹介・アフィリエイトリンクを含むなら `true`（必須）。表示側が本文より前に「PR・広告を含みます」を言語ごとに出す。
- `draft: true` は一覧に出ず、URL直打ちでも 404。
- `sources`: 本文で使った出典（`label`・`url`・`verified_at`）。制度の数字を書いたら必ず入れる。
- 本文で使えるMarkdown: `#`〜`###`、`- `、`1. `、`> `、`**太字**`、`[文字](https://…)`／`[文字](/navi)`。それ以外は使わない（`lib/markdown.ts`）。

## 書いてよいこと・いけないこと

- 制度・金額・期限の数字は、出典と確認日を添える。出典が無い数字は書かない。
- 医療的な判断（症状の見方、受診のタイミング、薬・サプリの効果）は書かない。「産院の指示に従ってください」で止める（設計原則10）。
- 施設の評価・おすすめ・ランキングを書かない。施設の並びは画面の「公表締切の週が早い順」だけ（設計原則8）。
- 病院の画面（/hospitals）から記事へリンクしない。記事から病院の画面へはよい。
- 個人（利用者・医療者）を特定できることを書かない。利用者の記録は集計だけ。

## 製品を載せるとき（アフィリエイト。弁護士確認後に開始）

- `pr: true` を付ける。本文の先頭にも1行「この記事には製品の紹介が含まれます」と書く（表示側の注記と二重でよい）。
- 選ぶ基準を記事の中に書く（例: 産院のリストにある品目、価格帯、入手しやすさ）。基準に「効果」を入れない。
- 「効く」「予防する」「安全」など、薬機法・健康増進法に触れる表現を使わない。医療機器は「◯◯として販売されているもの」とだけ書く。
- リンクの文字は商品名。「おすすめ」「必須」と書かない。
- 紹介料の有無で手続きの案内・病院の情報が変わらないことを、表示側の注記が明示する（`app/articles/[slug]/page.tsx`）。
- 各サービスの規約が求める文言（Amazon アソシエイトの表示など）は、決まったら `app/articles/[slug]/page.tsx` の PR 注記に足す。
- セット売りは「リンクのまとめ」（在庫を持たない）から。仕入れて発送する形は行わない（CLAUDE.md §7）。

## 英語版

- 直訳ではなく、日本の制度を知らない読者向けに、用語（母子手帳・一時金・出生届）は初出で日本語と英語を併記する。
- 数字と出典は日本語版と同じものを使う。片方だけ更新しない（`updated` をそろえる）。
- Navi本体はまだ日本語だけ。英語記事にはそのことを書き、`/navi` へのリンクを添える。

## 公開までの手順

1. 書く → `pnpm vitest run tests/articles.test.ts`（見出し情報・リンク・PRの検査）。
2. 出典のURLを開いて数字を確かめ、`verified_at` を今日にする。
3. `git push`（Vercel が自動でデプロイ）。
