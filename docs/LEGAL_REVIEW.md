# 弁護士に確認したいこと（段階1・試用の前後）

下書き: `content/legal/terms.md`（利用規約）、`content/legal/privacy.md`（プライバシーポリシー）。画面では `/terms` と `/policy` に「下書き」と明示して出している。
下書きは、コードが実際に保存・送信しているものに合わせて書いた（2026-09-19 時点）。実装を変えたら、この3つを一緒に直す。

## A. 個人情報・プライバシー

1. **そもそも個人情報にあたるか。** 名前を持たず、端末のランダムIDのハッシュだけで記録を持つ設計（`booking_reports` / `cost_reports` の `reporter_hash`）。メール通知を登録した人は、メールアドレス＋市区町村＋出産予定日＋完了チェックがサーバーで結びつく。後者は個人情報として扱う前提でよいか。
2. **要配慮個人情報。** 妊娠していること・出産予定日・分娩方法（経腟／帝王切開）・無痛分娩かどうかは、要配慮個人情報（病歴・診療等）にあたるか。あたる場合、取得時の同意の取り方は今の画面（同意のチェック、分娩方法は別の任意の同意）で足りるか。
3. **外国にある第三者。** Vercel（米国）、Supabase（米国法人。データは東京リージョン）、Resend（米国。メールアドレスと本文が渡る）。委託か提供か、本人への情報提供・同意の要否、ポリシーへの書き方。
4. **保存期間と削除。** 端末のデータを消した利用者は、自分の過去の記録を消せなくなる（端末IDが失われるため）。説明は `/privacy` に書いてあるが、これで足りるか。
5. **集計の出し方。** 金額の中央値は3件以上で表示、予約の記録は1件から表示。小さい件数での再識別のおそれと、しきい値の妥当性。
6. **IPアドレスのハッシュ**（回数制限用、1日で削除）をポリシーにどこまで書くか。
7. **未成年の利用**と保護者の同意。

## B. 医療・広告の規制

8. **医療広告ガイドライン。** 施設の一覧（出産なびの転載＋施設HPの予約ルール＋利用者の記録の集計）は、医療広告にあたらない整理でよいか。「おすすめ順ではありません」の表示、掲載料を受け取らない方針で足りるか。利用者の記録の集計（「予約できた◯件／満枠◯件」）は、体験談の広告にあたらないか。
9. **医療的判断を返さない**という線引き。「次にやること」に「産婦人科を受診し、胎児心拍を確認してもらう」を出すこと、妊娠週数を計算して表示することは問題ないか。
10. **出産なび（厚生労働省）の転載条件。** 出所の明記で足りるか。費用データの二次利用（実負担の計算に使う）の可否。
11. **段階4の製品紹介。** ステルスマーケティング規制（景品表示法）、アフィリエイトの表示、施設の画面と分ける設計で足りるか。

## C. 規約・責任

12. **免責の書き方。** 無料サービスで、期限や金額の「目安」を出す。情報の誤りで助成を受けそこなった場合などの責任の範囲を、消費者契約法に反しない形でどう書くか（全部免責は無効になりうる）。
13. **出典の無い行・確認中の行の扱い。** 「内容を確認中」「推定」「未確認」の表示が、注意喚起として十分か。
14. **メール通知**（特定電子メール法）。希望者だけ・確認メールで有効化・毎回の配信停止リンク・送信者の表示。送信者の名称と住所の表示が必要か。
15. **運営者の表示。** まずは個人で運営する（2026-09-19 決定）。個人の氏名・住所をどこまで表示する必要があるか（プライバシーポリシー、特定電子メール法の送信者表示）。特定商取引法の表示は、無料のあいだは不要でよいか。法人化の目安。
16. **試用（5家族）の段階**で、下書きのまま運用してよいか。試用の参加者に個別に説明・同意をもらうべき事項。
